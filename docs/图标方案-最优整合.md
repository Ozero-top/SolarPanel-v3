# 图标获取 / 加载 / 存储：最优整合方案

> 结论：**获取用 Sun-Panel 的"候选列表 + 用户点选"，存储与加载用 SolarPanel 原有的"host 去重 + WebP + 静态直出"**。
> 纯 Sun-Panel 实现（原图直存、无超时、无去重）和纯"页面按需抓取"都不适合本项目。

**Sun-Panel 模式带来的三个固有缺陷（已逐条修掉）**

1. 每次抓取生成新文件（`md5(url+时间戳)`）→ 反复抓同一站点会无限堆文件
2. 原图直存 → 1MB 的 180px 图标直接进首屏
3. `http.Client` 无超时 → 慢站长期占住后台 worker

## 2. 最优方案（五层）

### 获取层 —— Sun-Panel 的交互 + 服务端解析

- 后台点「获取站点图标」时，服务端抓站点页面，解析 `<link rel=...icon...>`（含 manifest），无候选回落 `/favicon.ico`
- 弹窗列出全部候选缩略图，**由用户点选**，不做自动选优（可控性优先，避免选到 16px 噪点图）
- 抓取约束：10s 超时、http/https、私网拦截、≤1MB、魔数校验
- 候选列表按请求缓存（重复点同一站点不重复抓页面）

### 存储层 —— 按站点去重 + 压缩

- 路径：`uploads/favicon/<md5(host)>.webp`，同一站点重抓覆盖旧文件
- 位图统一缩到 ≤64px 转 WebP（卡片实际显示 52~58px）
- SVG 过清洗后保存
- 写入前校验魔数与体积，HTML 错误页不会被当成图片

### 加载层 —— 静态直出 + 长缓存

- 卡片直接 `<img src="/frontend/uploads/favicon/<hash>.webp">`，同源、走 `Cache-Control: max-age=31536000, immutable`
- `loading=lazy` + `decoding=async`，`decode()` 完成后再淡入
- 首屏**不做服务端内联**（避免 `public.php` 变大、拖慢首屏）

### 兜底层 —— 永不阻塞首页

- 图标 404/解码失败 → 回退文字图标（标题首字，英文取大写首字母）
- 卡片数据不再依赖任何图标请求，图标缺失不影响打开速度

### 运维层 —— 可控的后台补图

- 存量 `favicon` 类型卡片：启动后台迁移，限批 30 张、并发 3
- 迁移失败写入 `settings.icon_migrate_skipped`，后续启动不再重试慢站
- 导入（HTML 书签 / Sun-Panel）默认文字图标，需要图标的用手动点选

## 3. 与"纯 Sun-Panel"的差异对照

| 维度 | Sun-Panel 原版 | 本项目（最优整合） |
| --- | --- | --- |
| 候选发现 | link[rel*=icon] + /favicon.ico | 同上（另兼容 manifest 与相对路径补全） |
| 选优 | 用户点选 | 用户点选（一致） |
| 超时 | 无 | 10s |
| 私网拦截 | 无 | 有 |
| 大小限制 | 1MB | 1MB + 魔数校验 |
| 图片处理 | 原图直存 | ≤64px WebP |
| 去重 | `md5(url+时间)`，不去重 | `md5(host)`，覆盖写 |
| 清理 | 无 | 同 host 旧扩展名自动删除 |
| 加载 | `/uploads/...` 直出，无缓存头 | 静态直出 + 1 年 immutable |
| 失败回退 | 无（裂图） | 文字图标 |

## 4. 迁移与验收

**升级后**

1. 存量 141 张指向 `uploads/favicon/` 的卡片继续可用（存储层路径未变）
2. 5 张仍为 `favicon` 类型的卡片会在后台迁移一次；失败记录后不再重试
3. 新导入的卡片默认文字图标，需在后台手动选图

**验收清单**

- [ ] 后台点「获取站点图标」能弹出候选网格，点选后卡片立即显示
- [ ] 同一站点重复点选，`uploads/favicon/` 下不产生新文件（文件数为站点数量量级）
- [ ] 保存后的文件为 `.webp`，体积多在 1–4KB
- [ ] 慢站点（如超时站点）点击后 10s 内返回失败提示，不卡住其它请求
- [ ] 首页 `public.php` 响应体不再包含图标 data URL
