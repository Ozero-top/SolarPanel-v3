# Sun-Panel 与 SolarPanel 图标获取/加载/存储方案对比报告

> 分析对象：`示例/sun-panel-latest.tar`（OCI 镜像，内含 Go 后端 + Vue 前端）
> 对比对象：当前项目 SolarPanel 3.0
> 结论先行：**工程能力上 SolarPanel 现有方案明显更强；产品灵活性上 Sun-Panel 有两点值得借鉴。不建议把 SolarPanel 改成 Sun-Panel 的实现方式。**

---

## 1. 分析方法与边界

- 解包镜像 layer，叠加得到 rootfs；确认后端为 Go 1.21.10 单二进制，前端为 Vue3 + Naive UI，运行时数据目录 `/app/conf`，上传目录配置项 `source_path=./conf/uploads`。
- 通过 `go tool nm`、`go tool objdump -s` 恢复关键函数与调用链，并解码 ELF 中的字符串常量；同时对照前端 bundle 中的接口调用与渲染逻辑。
- 二进制中可看到 `v1.8.1` 字样，但 `getSiteFaviconList`、`downloadFavicon`、`imageProxy`、`uploadFaviconImage` 等接口并不在公开仓库的 v1.8.1/dev 源码中（判断为私有构建或后续改动）。因此本报告以**二进制实际实现**为准，公开源码仅用于交叉理解。
- SolarPanel 部分基于仓库内真实代码，引用见文末。

## 2. Sun-Panel 逆向结果

### 2.1 关键路由与调用链

图标相关路由（后端）：

```
/panel/itemIcon/getSiteFavicon        # 旧接口：返回第一个候选图标
/panel/itemIcon/getSiteFaviconList    # 新接口：返回候选图标列表
/panel/itemIcon/downloadFavicon       # 选定候选后下载并落盘
/panel/itemIcon/imageProxy            # 远程图片直通代理
/panel/itemIcon/addMultiple | edit | deletes | saveSort | getListByGroupId ...
/panel/globalSetting/uploadFaviconImage  # 仅 .ico 上传
/api/file/uploadImg                   # 前端实际使用的通用图片上传
```

### 2.2 数据模型

- `item_icons` 表：图标配置以 JSON 存放在 `icon_json`（`varchar(1000)`）列中；API 层用 `Icon string gorm:"-" json:"icon"` 做出入参（不直接落库）。
- 图标 JSON 对应三种类型：
  - `itemType=1`：文字图标（`text`）
  - `itemType=2`：图片图标（`src`，可为远程 URL 或本地 `/uploads/...`）
  - `itemType=3`：图标字体（icon class，走图标库）
- 卡片渲染分支：`itemType=2` 时，`.svg` 用原生 `<img>`，其余用 Naive UI `Image` 组件；**图片加载失败没有回退到文字图标的逻辑**。

### 2.3 获取（发现候选 → 选定 → 下载）

1. **候选发现（服务端）** `GetSiteFaviconList`：
   - 用默认 `http.Client` GET 站点页面（**无超时**），状态码非 200 直接报错；
   - goquery 遍历所有 `<link>`，取 `rel` 中用 `strings.Index` 匹配子串 `"icon"`（**大小写敏感**）且 `href` 非空的项；
   - 用 `url.Parse` + `ResolveReference` 把相对地址补成绝对地址；
   - 若页面没有候选，回退到 `scheme://host/favicon.ico`；
   - 返回 `{list, count}`，前端把候选图片列出来让用户点选。
   - 旧接口 `GetSiteFavicon` 直接返回列表第一个。
   - 页面抓取失败时直接报错，**没有服务端公共图标源兜底**。

2. **下载落盘** `DownloadFavicon` → `biz.DownloadFileAndSaveDb`：
   - `GetRemoteFileSize` 先发 **HEAD**，状态码必须为 200；HEAD 失败则整个下载失败；
   - 大小上限 **1 MB**（调用方传入 `0x100000`），超过即失败；
   - 再 `http.Get` 下载，状态码必须为 200；**默认 Client，无超时**；
   - 文件名 = `md5(url + time.Now())` + `path.Ext(url)`，**不去重**；
   - 保存到 `<source_path>/YYYY/MM/DD/`（默认 `/app/conf/uploads`）；
   - 写入 `files` 表（模型 `File`），返回 `/uploads/YYYY/MM/DD/<md5>.ext`。

3. **上传**：
   - `uploadFaviconImage`：仅允许 `.ico`，走 `UploadFileAndSave`；
   - `/api/file/uploadImg`（前端实际使用）：允许 `.png .jpg .gif .jpeg .webp .svg .ico .avif .heic`；
   - 两者都只做**后缀白名单**，不校验 MIME/文件头；`maxSize=0` 在内部表示**不限制大小**（`strlen`/size 校验被跳过）。

4. **imageProxy** `?imageUrl=`：
   - 直接 `http.Get` 后 `io.Copy` 输出；
   - 不检查上游状态码、不设置 `Content-Type`/缓存头、无超时、无大小限制、无内网/回环地址拦截（存在 SSRF 面）；
   - 当前 Web bundle **没有调用**该接口，属于遗留/其他端能力。

### 2.4 加载

- 落盘后的图标通过 `/uploads/...` 静态目录直出，同源加载，无 CORS/防盗链问题。
- 没有服务端缩放、格式转换、缓存头、ETag、批量接口或首屏内联。
- 前端卡片按 `src` 直接加载图片，无失败兜底；图标质量完全取决于第一次抓到的文件。

### 2.5 存储

| 项目 | Sun-Panel 做法 |
| --- | --- |
| 文件位置 | `<source_path>/YYYY/MM/DD/`，默认 `/app/conf/uploads` |
| 文件名 | `md5(URL + 时间戳) + 原扩展名`，重复抓取会产生新文件 |
| 元数据 | `files` 表记录；图标 JSON 的 `src` 指向 `/uploads/...` |
| 过期/清理 | 无 TTL、无自动清理、无去重 |
| 大小治理 | 下载 1 MB 上限；**上传无上限** |
| 内容校验 | 仅扩展名白名单，不验证文件头/MIME |
| 缓存 | 无服务端缓存层、无缓存头 |

### 2.6 主要问题清单

1. 页面请求、HEAD、GET 全部使用默认 Client：**无超时**，慢站会长期占用请求。
2. HEAD 强依赖：目标站不支持 HEAD、返回非 200 或无 Content-Length 时，图标下载直接失败。
3. 无 SSRF 防护：站点抓取、图标下载、imageProxy 均可访问任意地址（需管理员权限，但仍是风险）。
4. 候选只按 HTML 顺序取，不比较清晰度；`rel` 大小写敏感；不解析 manifest、不区分 apple-touch-icon 质量。
5. 文件不压缩、不缩放，常见 48/64/180px 原图直接用于小卡片；无 WebP。
6. 无去重、无清理、上传无大小上限：长期运行会产生冗余文件，极端情况可撑爆磁盘。
7. 上传只查后缀，`.svg` 原样入库并静态直出，存在同源内容风险（需管理员权限）。
8. 图标一旦落盘即“永久”，站点换图标后不会刷新（除非用户手动重新抓取）。

## 3. SolarPanel 现有方案

### 3.1 获取

- 图标类型：`text` / `image` / `favicon`（[items_handler.go](file:///f:\编程\SolarPanel%203.0\SolarPanel\internal\handler\items_handler.go#L62)）。
- `favicon` 型由后台“获取站点图标”触发 `GET /api/items.php?action=favicon&url=...`，仅 admin/editor 可用（[items_handler.go](file:///f:\编程\SolarPanel%203.0\SolarPanel\internal\handler\items_handler.go#L656-L694)）。
- 候选来源（[favicon_resolver.go](file:///f:\编程\SolarPanel%203.0\SolarPanel\internal\handler\favicon_resolver.go#L130-L176)）：
  - 解析 HTML `<link>`，按 `rel` 类型打分（icon / shortcut icon / apple-touch-icon / mask-icon 等）；
  - 解析 web manifest 的 icons；
  - 站点根默认路径（`/favicon.ico`、`/favicon.png`、`/apple-touch-icon.png` 等）。
- 抓取策略（[favicon_resolver.go](file:///f:\编程\SolarPanel%203.0\SolarPanel\internal\handler\favicon_resolver.go#L283-L316)）：
  - 最多 12 个候选并发抓取，单个 5s 超时；
  - 首个可用结果到达后，再等 600ms 收集更优候选；
  - 质量评分 = 声明尺寸 + 真实像素 + 文件体积 + SVG 加权（[favicon_resolver.go](file:///f:\编程\SolarPanel%203.0\SolarPanel\internal\handler\favicon_resolver.go#L254-L281)）。
- 网络与安全（[items_handler.go](file:///f:\编程\SolarPanel%203.0\SolarPanel\internal\handler\items_handler.go#L323-L369)）：
  - 只允许 http/https；
  - 私网地址拦截（含重定向目标）；
  - 5s 超时、2MB 上限、Content-Type/魔数校验；
  - SVG 会走清洗（[favicon_image.go](file:///f:\编程\SolarPanel%203.0\SolarPanel\internal\handler\favicon_image.go)）。
- 兜底：
  - 服务端公共图标源两轮（[items_handler.go](file:///f:\编程\SolarPanel%203.0\SolarPanel\internal\handler\items_handler.go#L439-L453)）；
  - 前端代理失败后再串行回退 `favicon.cccyun.cc`、`favicon.im`（[api.js](file:///f:\编程\SolarPanel%203.0\SolarPanel\frontend\assets\js\api.js#L348-L356)）；
  - 全部失败回退文字图标。

### 3.2 加载

- 服务端代理 `GET /api/favicon.php?host=...`（[favicon_proxy.go](file:///f:\编程\SolarPanel%203.0\SolarPanel\internal\handler\favicon_proxy.go#L90-L183)）：
  - 命中磁盘缓存直接返回，未命中现场抓取并落盘；
  - 响应带内容 ETag，`Cache-Control: public, max-age=31536000, immutable`（[favicon_proxy.go](file:///f:\编程\SolarPanel%203.0\SolarPanel\internal\handler\favicon_proxy.go#L256-L282)）；
  - 404 也带 1 小时短缓存，避免反复回源（[favicon_proxy.go](file:///f:\编程\SolarPanel%203.0\SolarPanel\internal\handler\favicon_proxy.go#L234-L237)）。
- 批量接口 `?hosts=a,b,c`：最多 48 个 host、192KB 总量、只读磁盘不联网、ETag + 600s 共享缓存（[favicon_proxy.go](file:///f:\编程\SolarPanel%203.0\SolarPanel\internal\handler\favicon_proxy.go#L185-L231)）。
- 首屏内联：前 8 张、总计 24KB 的图标直接以 data URL 随卡片接口返回（[public_handler.go](file:///f:\编程\SolarPanel%203.0\SolarPanel\internal\handler\public_handler.go#L248-L292)）。
- 前端（[index.js](file:///f:\编程\SolarPanel%203.0\SolarPanel\frontend\assets\js\index.js#L2608-L2779)）：
  - 前 10 张高优先级直载，其余 IntersectionObserver 懒加载（200px 预取）；
  - IndexedDB 缓存已取到的图标；
  - 80ms 内的域名合并为一次批量请求（上限 48），2.5s 兜底回退逐卡代理；
  - 服务端内联 → IndexedDB → 批量 → 代理 → 公共源 → 文字图标的多级回退；
  - `decode()` 完成后再淡入，避免解码掉帧；`referrerPolicy=no-referrer`。
- 启动预热：后台预热已有 favicon 类型站点（[favicon_prewarm.go](file:///f:\编程\SolarPanel%203.0\SolarPanel\internal\handler\favicon_prewarm.go)）。

### 3.3 存储

- 路径：`<UploadDir>/favicon/<md5(host)>.<ext>`，按 host 唯一，天然去重（[favicon_proxy.go](file:///f:\编程\SolarPanel%203.0\SolarPanel\internal\handler\favicon_proxy.go#L92-L110)）。
- 位图统一缩到 ≤64px 并转 WebP（质量 78）；SVG 清洗后保存（[favicon_image.go](file:///f:\编程\SolarPanel%203.0\SolarPanel\internal\handler\favicon_image.go)）。
- 写入前校验魔数/内容，过小数据丢弃，避免 HTML 错误页当图片缓存。
- 缓存超过 90 天自动删除并按需重抓（[items_handler.go](file:///f:\编程\SolarPanel%203.0\SolarPanel\internal\handler\items_handler.go#L373-L389)）。
- 上传图标：5MB 上限 + 扩展名白名单 + SVG 清洗 + 时间戳随机文件名（[upload_handler.go](file:///f:\编程\SolarPanel%203.0\SolarPanel\internal\handler\upload_handler.go)）。
- 数据库只存 `icon_type` / `icon_value`，favicon 的文件路径由 host 推导，不落库（[db.go](file:///f:\编程\SolarPanel%203.0\SolarPanel\internal\db\db.go)）。

## 4. 逐维度对比

| 维度 | Sun-Panel | SolarPanel | 占优 |
| --- | --- | --- | --- |
| 候选发现 | link[rel*=icon] + 默认 `/favicon.ico` | link 评分 + manifest + 多默认路径 | SolarPanel |
| 选优能力 | 用户手动点选（可控性好） | 自动质量评分选最优（无候选列表） | 各有所长 |
| 抓取健壮性 | 无超时、无重试、HEAD 强依赖 | 5s 超时、并发、600ms 聚合、两轮兜底 | SolarPanel |
| 公共源兜底 | 无（仅前端可能回退） | 服务端 4 个 + 前端 2 个 + 文字兜底 | SolarPanel |
| 安全防护 | 无 SSRF 校验、无 MIME 校验 | 私网拦截、重定向限制、魔数校验、SVG 清洗 | SolarPanel |
| 大小限制 | 下载 1MB，上传无限制 | 抓取 2MB，上传 5MB | SolarPanel |
| 图片处理 | 原图直存 | ≤64px WebP + 质量 78 | SolarPanel |
| 存储去重 | md5 含时间，重复产生新文件 | host 级唯一路径，天然去重 | SolarPanel |
| 文件清理 | 无 | 90 天过期自动清理 | SolarPanel |
| 缓存策略 | 无缓存头/无 ETag/无批量 | 1 年 immutable + ETag + 批量 + 内联 + IndexedDB | SolarPanel |
| 首屏性能 | 逐图直连 | 内联 + 批量 + 懒加载 + 解码淡入 + 预热 | SolarPanel |
| 图标类型 | 文字 / 图片 / 图标字体 / 在线图标库 | 文字 / 图片 / favicon | Sun-Panel |
| 文件管理 | 统一 files 表与上传目录 | 按用途分目录，无文件库概念 | Sun-Panel |
| 实现复杂度 | 低 | 高（但模块清晰） | Sun-Panel |

## 5. 结论

1. **整体工程能力：SolarPanel 现有方案更有优势。**
   在弱网 NAS 场景下，SolarPanel 的超时、并发、质量选优、WebP 压缩、host 去重、磁盘缓存、批量接口、首屏内联和前端 IndexedDB 组合，解决的是 Sun-Panel 完全没有覆盖的问题：成功率、首屏延迟、长期存储治理与安全。

2. **Sun-Panel 的两点产品优势值得保留借鉴：**
   - **候选列表让用户选择**：用户能看到站点提供的多个图标并手动挑一个，比“自动选优”更可控；SolarPanel 目前没有候选列表 UI。
   - **图标类型更丰富**：图标字体/在线图标库 + 统一文件管理，适合喜欢自定义视觉的用户。

3. **不建议照搬 Sun-Panel 的实现：**
   它的抓取链路缺少超时、SSRF 防护、MIME 校验、大小治理与清理，长期运行隐患明显；这些正是 SolarPanel 已经做好的部分。

4. **如果只做一个增量改进**：在 SolarPanel 后台的“获取站点图标”里增加“候选列表 + 手动选择 + 重新抓取”，复用现有抓取与落盘逻辑，成本最低、收益最直接。存储与加载层保持现状不动。
